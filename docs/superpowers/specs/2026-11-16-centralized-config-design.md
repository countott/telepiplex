# Telepiplex 集中配置设计

## 目标与当前授权

用户要求按“先清理代码，再整理策略，再落地集中化”的顺序，将配置集中到顶层 `config.yaml`，并按用途分区。插件安装、更新后直接使用对应配置，不再要求维护各插件的私有 YAML。用户已明确保留 Telegram `/config` 编辑，所有修改统一写入顶层配置。

本设计取代当前“Host 不持有业务配置、Feature 私有 YAML 各自权威”的配置归属约定。插件仍独立安装、更新、回滚；业务实现与运行状态仍归插件所有。

Mac 仅修改和验证本地源码，不执行 Git，不发布。现行 AGENTS.md 中的路径及 Syncthing 边界优先于历史文档。

## 第一阶段：先清理代码

已确认 Rename 当前整理链读取已确认的 `media_metadata`，必要时调用 AI，没有调用旧 `tvdb.py` 的 TVDB API。删除该闲置模块及其独立适配器测试，删除 Rename 的 TVDB 默认值、schema、向导入口及运行时透传；保留 `tvdb_rename.py` 中的确认方案整理和所有媒体身份规则。使用声明式配置迁移移除旧 `metadata` 区块，保留用户的 AI、目录及整理策略。

Caption 仅收敛完全相同的 provider JSON Schema 定义，使用本地 `$defs/$ref`；不改变接受的配置、来源策略或运行行为。

不先建设通用配置向导引擎。后续集中化会保留现有业务向导，避免先抽象、后拆除。

## 方案取舍

1. **继续分散保存，仅统一菜单**：改动小，但用户仍需维护多个权威文件，不满足本次要求。
2. **一份顶层 YAML，Host 投影插件配置**：采用此方案。用户只维护一份文件，插件继续消费已验证的自身配置；独立发布协议可渐进兼容。
3. **所有插件直接读写完整主 YAML**：不采用。并发写入容易相互覆盖，插件会接触无关配置，授权刷新和更新回滚也会牵动整份文件。

## 第二阶段：配置分区和归属

唯一权威文件保持 `/config/config.yaml`。源码模板保持 `config/config.yaml.example` 与 `app/config.yaml.example` 一致。

```yaml
config_version: 2

# Bot、日志
log_level: info
bot_token: ""
allowed_user: 123456789

# 插件安装与运行环境，继续使用既有 plugins 技术键
plugins:
  root: /config/plugins
  # catalog、超时、事件投递等现有参数

# 跨插件共用的事实
shared:
  category_folder:
    - kind: live_action_movie
      name: 真人电影
      path: /真人电影
      plex_library_id: ""
    # 其余三个固定 kind：animated_movie、live_action_series、animated_series
  tmdb:
    api_key: ""  # TMDB API Read Access Token

# 按插件分区的服务参数与业务策略
features:
  download: {}  # 115 授权、保存目录、清理阈值、API 调用策略
  search: {}    # Prowlarr、搜索评分、元数据来源及其各自策略
  rename: {}    # 未整理目录、文件映射 AI、整理及字幕交接策略
  sync: {}      # Plex、Fanart、扫描及 MCP
  caption: {}   # 字幕来源、各源授权、输出与检索预算
```

最终模板完整列出可编辑字段与默认值，不以这里的空映射代替完整说明。原有技术字段名保持不变，`features.search.search` 等内部层级先保留，以保证旧插件投影契约与 schema 不变；模板通过清楚的区块注释说明用途，不同时进行无关的字段重命名。

`shared.category_folder` 是 Search、Rename、Sync 共用的四分类目录及 Plex 库映射。它有统一的四分类默认值，不再让 Sync 的空数组与另外两个插件的默认值分叉。按 `kind` 识别分类，不按显示名称、数组顺序识别。

`shared.tmdb.api_key` 供 Search 与 Sync 使用。只共享语义一致的凭据；Search 的启停、接口地址与超时，Sync 的请求超时分别留在各自分区。Sync 不接收其 schema 未声明的 Search 专有字段。

TVDB 当前由 Search 负责；AI 当前由 Rename 负责，不为了形式统一而增加无消费者的公共区。Prowlarr、115、Plex、Fanart、字幕源授权分别在对应插件区维护。

各级 timeout、enabled/enable 和业务预算保持原有语义，显式的 `false`、`0`、空字符串与空列表不会被 `or default` 无意覆盖。评分表等用户映射按现有语义保留，不对显式空表补回默认评分。

插件包中的 `config.default.yaml` 和 `config.schema.json` 仍是默认值与校验契约，属于安装包，不再是用户维护的第二份权威配置。未安装插件的配置允许预先填写；未知插件使用 `features.<plugin_id>`，不硬编码只允许五个插件。

## 第三阶段：集中化实现边界

### 主配置存储与投影

新增集中配置存储模块，单个 Host 写入入口负责锁内重读、路径级补丁、修订或预期值检查、校验、`fsync` 及 `0600` 原子替换。写入保留无关分区、未知插件字段与未安装插件配置，不能用某个插件的旧快照重写整份文件。

`PluginStore` 使用集中后端读取、准备和提交插件配置。插件独有配置按该 release 默认值与显式用户值合成；公共值只由公共区投影。普通启动、安装、更新、启用、回滚和 `/reload` 均走同一投影与校验入口。

缺省只补缺失键，不以真假判断补值；列表整体处理。需要允许显式空映射的策略字段保持原有行为。无效配置报安全字段路径，不回显值。

Supervisor 为每个进程实例生成只含该插件配置的 `0600` 生效快照，保存在运行时目录。`TPX_CONFIG_PATH` 指向该快照。快照由 Host 重建，不是用户编辑入口；不向插件下发主配置文件路径。旧插件继续读取既有平面结构，包内 schema 不因主文件布局而整体重写。

### Telegram 编辑与共享设置

保留 `/config` 与既有插件向导、敏感值不回显、草稿及确认保存流程。增加公共分类路由与 TMDB 凭据的清晰入口；原 Search/Sync TMDB 凭据入口映射到同一个公共值。

向导返回的原始嵌套 `config_patch` 直接进入 Host 的补丁事务，不能先扩成完整旧配置再保存，以免固化默认值或覆盖刚刷新的 Token。插件独有设置只重载对应插件；共享值修改找出所有已安装消费者，统一校验并协调生效。未启用或未安装的插件不必为了保存配置临时启动。

配置成功反馈说明保存到主配置并列出实际重载结果；失败保留草稿或给出明确失败，不能显示成功。

### 115 授权刷新及主动授权

Download 保留实时 Token 持久化能力，但集中模式通过认证的 Host RPC 更新自己分区的授权字段。不得把整个主文件交给 Download 写入，也不能让本地快照成为权威来源。

配置写 RPC 绑定插件身份和进程实例，仅允许 Download 更新已声明的授权/下载配置字段，拒绝跨区、共享区及任意路径写入。使用预期旧值或修订保护，旧进程、失效授权操作和取消后的回滚不能覆盖新 Token。Shadow 进程在候选阶段不能提交权威配置。

授权取消恢复只恢复该次授权拥有的字段，并检查当前值仍是该事务写入值；不恢复整份 YAML，不撤销别处的新修改。成功的实时写入同时更新 Host 的运行配置记录，后续失败恢复不能拿缓存的旧 Token 覆盖它。

### 安装、更新、重载和回滚

插件安装后自动取得主配置对应区及包内默认值。缺少服务凭据不伪造已配置状态；现有未配置诊断与业务入口仍按原规则提示。安装更新不覆盖用户已有值。

安装包 stage/commit 可以准备候选默认值与迁移结果，但候选未健康前不提交权威主配置。配置事务先准备投影及 schema 校验，安全排空相关旧进程，启动候选并验证，再提交所拥有的路径和切换路由。失败恢复旧路由、旧进程和该事务拥有的字段，保留其他分区及最新授权值。

`/reload` 重新读取主 YAML 并验证；解析或校验失败时继续运行旧配置。手工编辑的无效文件保留给用户修正，不悄悄改回旧文件。共享值成功重载后所有运行消费者一致；反馈真实报告失败，不能出现一部分使用旧共享值却整体报告成功。

用户主动执行插件版本回滚时，保留主配置中的最新独有值，再按目标 release 的默认值和 schema 生成候选；共享凭据、公共媒体路由和最新 Download 授权均不随代码版本倒退。目标 schema 无法接受当前配置时拒绝回滚并报告字段路径，不静默恢复升级前的业务设置。历史配置快照仅用于撤销尚未成功的激活事务，不作为成功版本回滚时的默认设置来源。

### 旧 Download 的兼容门槛

旧 Download 会把 Token 写入 `TPX_CONFIG_PATH`；集中后该路径只是运行快照，不能继续把旧写入误认为持久化成功。新的 Download manifest 显式声明支持 Host 配置写入协议，Host 对需要动态持久化的 Download 检查此声明。

集中模式不启动、启用或回滚到不支持该协议的旧 Download。Host 本身仍启动，并在插件诊断中提示更新 Download；允许用户从 Telegram 安装/更新到兼容版本，然后读取已经迁入主配置的旧授权。拒绝旧版激活时保留当前运行实例、配置和任务状态，不添加双写或监视旧快照的隐式兼容机制。新的声明和 Host API 最低版本在实际实现时同步更新，包版本在完整改造后统一调整。

### 旧配置迁入

检测到旧布局时，读取 `/config/plugins/<plugin_id>/config.yaml`，先准备完整迁移候选、校验全部已安装插件，再原子写入主文件并记录 `config_version: 2`。原文件保留为历史备份，不删除、不继续读取为权威来源。新运行快照使用不同路径，避免被当作旧配置再次导入。

主文件已存在的显式新配置优先；旧文件只用于首次迁入，不在每次启动反向同步。公共分类路由按 `kind` 合并缺失项，空的 Sync 列表可忽略；非空路径或库 ID 互相冲突时停止迁移并报告来源及字段路径，不擅自选一个。多个非空 TMDB 凭据不一致也停止，且不在错误中输出凭据。

旧 Rename TVDB 区块已由清理阶段迁移删除，不提升到公共区。原插件的声明式迁移继续在合适的 schema 版本间应用，失败不能丢弃未知用户值或绕过校验。

## 验证与交付

- 清理阶段：Rename 完整测试；Caption schema 前后等价检查及完整测试。
- 集中存储：默认合成、显式空/零/false、跨区保留、并发补丁、写入失败、权限及重启恢复。
- 首次迁移：五插件旧值迁入、缺失/未安装插件、公共值冲突、秘密不回显、原文件保留、重复启动幂等。
- 真实配置链：Telegram 草稿确认、仅补丁保存、公共设置多消费者重载、取消与失败恢复。
- 115：刷新和授权写回主文件、旧实例拒写、取消不覆盖新 Token、其他插件配置不被修改。
- 安装/更新/回滚：生效快照、包内默认更新、用户值保留、失败保留旧进程与路由。
- 最终执行 Host 与五个 Feature 的完整本地测试；记录实际结果及未运行项目，不复用旧轮次结果。
- 列出新增/修改/删除文件及用途，等待 Syncthing `Up to Date / 最新` 后由用户在 Unraid `/mnt/user/archives/Life Hacker/Telepiplex` 检查和发布。
