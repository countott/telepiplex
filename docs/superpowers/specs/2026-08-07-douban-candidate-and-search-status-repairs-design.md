# 豆瓣候选与搜索状态修复设计

## 目标

修复搜索流程中已经复现的四类用户可见问题，同时保持
`media_metadata v1` schema、确认后身份展示和其他 Feature 行为不变。

## 范围

### 搜索器状态

搜索器状态必须先计算可用总数，不得把算式直接显示给用户。

- `total`：启用搜索器总数。
- `failed`：所有查询变体均失败的搜索器数量。
- `available = max(0, total - failed)`。
- `successful_completed = max(0, completed - failed)`。
- 显示格式：`搜索器 successful_completed/available，失败 failed`。

例如，三个搜索器中两个失败时显示 `搜索器 0/1，失败 2`，不得显示
`搜索器 0/(3-2)，离线 2`。

### 豆瓣标题合并

豆瓣第一轮摘要可能只返回组合标题，例如 `想见你 想見你`，并且没有
独立 `original_title`。详情端点补充 `original_title=想見你` 后，合并逻辑
必须重新计算依赖该字段的派生标题：

- `chinese_title=想见你`
- `original_title=想見你`
- `official_english_title=Someday or One Day`

确认后的身份展示继续使用 `中文标题 (官方英文标题)`，例如
`想见你 (Someday or One Day)`。

### 豆瓣候选展示

候选正文、候选详情和选择按钮统一使用：

`中文标题 (原标题) 年份`

- 原标题缺失时省略括号。
- 原标题规范化后与中文标题相同时省略括号。
- 年份缺失时显示 `年份未知`。
- 候选阶段不再另起一行显示官方英文标题。
- 长按钮文案截断标题组件时必须保留括号结构和年份。
- 该规则只影响候选阶段；不改变确认后的身份展示。

示例：

- `想见你 (想見你) 2019`
- `让子弹飞 2010`

### 海报宫格

豆瓣 CDN 图片请求使用适配的请求头，并保持只接受 HTTPS、限制响应体大小
和验证图片解码的安全边界。

- 豆瓣图片主机请求增加豆瓣电影页 `Referer`、图片 `Accept` 和语言请求头。
- 日志只记录候选编号、图片主机和失败类型，不记录完整 URL。
- 部分图片失败时，失败卡片中央显示候选中文标题，底部保留候选编号。
- 长标题在卡片内自动换行，超出空间时使用省略号。
- Core 容器安装 Noto CJK 字体，保证 Unraid 运行时能实际绘制中文而不是方框。
- 至少一张图片成功时仍生成宫格。
- 存在远程海报地址但零张图片成功时抛出明确的宫格不可用错误，由现有
  Host 渲染路径降级为同一份文本候选和按钮。

## 非目标

- 不修改 `media_metadata v1` schema。
- 不改变确认后的 `中文标题 (官方英文标题)` 展示规则。
- 不改变单张海报由 Telegram 直接读取的路径。
- 不修改版本号、配置模板或发布工作流。
- 不在 Mac 工作区执行任何 Git 操作。

## 验证

- 豆瓣摘要缺少 `original_title`、详情补充原标题的回归测试。
- 候选正文、详情、按钮和可选原标题测试。
- 搜索器计数完成态、增量态和零搜索器测试。
- 豆瓣图片请求头、标题占位、部分成功和全部失败测试。
- Feature 动作和 Host 文本降级测试。
- search Feature 全量测试、Core 全量测试以及工作区边界检查。
